# Day 07 – Linux File System Hierarchy & Scenario-Based Practice

# Part 1 – Linux File System Hierarchy


### 1. `/` (Root)

- The root directory is the starting point of the Linux file system.
- Every file and directory exists under `/`.

**Command Used:**

```bash
ls -l /
```

**I would use this when:**
I need to understand the overall file system structure.

---

### 2. `/home`

- Contains home directories of normal users.
- User-specific files and folders are stored here.

**Command Used:**

```bash
ls -l /home
```

**I would use this when:**
I need to access or manage user files.

---

### 3. `/root`

- Home directory for root user.
- Used for administrative tasks.

**Command Used:**

```bash
sudo ls -l /root
```

**I would use this when:**
I need to access files belonging to the root user.

---

### 4. `/etc`

- Contains system and application configuration files.
- Most service settings are managed from this directory.

**Command Used:**

```bash
ls -l /etc
```

**I would use this when:**
I need to check or modify service configurations.

---

### 5. `/var/log`

- Stores log files generated by the system and applications.
- Very important for troubleshooting.

**Command Used:**

```bash
ls -l /var/log
```

**I would use this when:**
Checking logs to diagnose application or system issues.

---

### 6. `/tmp`

- Stores temporary files.
- Files may be deleted automatically after reboot.

**Command Used:**

```bash
ls -l /tmp
```

**I would use this when:**
I need temporary storage for testing or troubleshooting.

---

### 7. `/bin`

- Contains essential Linux commands.
- Commands such as `ls`, `cp`, `mv`, and `cat` are available from here.

**Command Used:**
```bash
ls -l /bin
```

**I would use this when:**
I want to know where important command binaries are stored.

---

### 8. `/usr/bin`

- Contains commonly used user commands and programs.

**Command Used:**
```bash
ls -l /usr/bin
```

**I would use this when:**
I need to find installed command-line tools.

---

### `/opt`

- Used for installing third-party software.

**Command Used:**
```bash
ls -l /opt
```

**I would use this when:**
Installing or managing third-party applications.

---

# Part 2 - Scenario-Based Practice

## Scenario 1: Service Not Starting

```
A web application service called 'nginx' failed to start after a server reboot.
What commands would you run to diagnose the issue?
Write at least 4 commands in order.
```

**Problem:** Nginx failed to start after a server reboot. What commands would you run to diagnose and fix the issue?

### Solution 

**Step 1:** Check service status

```bash
systemctl status nginx
```

**Why:**
Checks whether the Nginx service is running, stopped, or failed, and shows recent error details.

**Step 2:** View recent Nginx logs

```bash
journalctl -u nginx -n 50
```

**Why:**
Displays the last 50 log entries for Nginx to identify the reason it failed.

**Step 3:** Check if Nginx is enabled on boot

```bash
systemctl is-enabled nginx
```

**Why:**
Checks whether Nginx is enabled to start automatically when the server boots.

**Step 4:** Restart the service after fixing the issue

```bash
systemctl restart nginx
```

**Why:**
After fixing any identified issue, attempts to restart Nginx and verify that it starts successfully.

### What I Learned 

Always check the service status first, then review the logs, verify if the service is enabled on boot, and restart it after fixing the issue.

## Scenario 2: High CPU Usage

```
Your manager reports that the application server is slow.
You SSH into the server. What commands would you run to identify
which process is using high CPU?
```
**Problem:** 
The application server is responding slowly and CPU utilization is very high.

### Solution 

**Step 1:**

```bash
top
```

**Why:**
Monitor CPU usage in real time.

**Step 2:**

```bash
ps aux --sort=-%cpu | head -10
```

**Why:**
Display the top CPU-consuming processes.

**Step 3:** 
```bash
ps -fp <PID>
```

**Why:**
Get detailed information about the identified process.

**Step 4:**

```bash
top -p <PID>
```

**Why:**
Monitor the CPU usage of the specific process.

### What I Learned

CPU problems can be identified by checking live CPU usage and finding the processes consuming the most CPU.

## Scenario 3: Finding Service Logs

```
A developer asks: "Where are the logs for the 'docker' service?"
The service is managed by systemd.
What commands would you use?
```
**Problem:**
Where can you find the logs for the docker service?

### Solution 

**Step 1:**

```bash
systemctl status docker
```

**Why:**
Verify whether the Docker service is running.

**Step 2:**

```bash
journalctl -u docker -n 50
```

**Why:**
View the latest Docker service logs to identify errors.

**Step 3:**

```bash
journalctl -u docker -f
```

**Why:**
Monitor Docker logs in real time.

**Step 4:**

```bash
docker logs <container_id>
```

**Why:**
Check logs generated by a specific Docker container.

### What I Learned

Systemd-managed services store logs in the journal and can be accessed using `journalctl`. Container-specific logs can be viewed using the `docker logs` command.

## Scenario 4: Permission Denied Error

```
A script at /home/user/backup.sh is not executing.
When you run it: ./backup.sh
You get: "Permission denied"

What commands would you use to fix this?
```
### Problem

A script named `backup.sh` shows "Permission denied" when executed.

### Solution 

**Step 1:**

```bash
ls -l /home/user/backup.sh
```

**Why:**
Check the current file permissions.

**Step 4:**

```bash
chmod +x /home/user/backup.sh
```

**Why:**
Add execute permission to the script.

**Step 3:**

```bash
ls -l /home/user/backup.sh
```

**Why:**
Verify that the execute permission was added.

**Step 4:**

```bash
./backup.sh
```

**Why:**
Execute the script after correcting its permissions.

### What I Learned

Check the file permissions first, then add execute permission using chmod +x.
